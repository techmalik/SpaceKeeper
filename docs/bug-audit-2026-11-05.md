# Bug audit — 5 November 2026

Base: `7cf8e47` on `main`. Fix branch: `codex/bug-audit-fixes`.

Reviewed the Swift application sources, package/build scripts, and CI workflow. This is a source audit with automated
regression checks, not a claim that every macOS interaction or OS version has been verified.

## Findings fixed

| Area | Trigger and original failure | Change |
| --- | --- | --- |
| Window moves | A full-screen Space sits between two desktops; Next/Previous selected the full-screen Space itself. | Resolve destinations among regular desktops; count intervening Spaces for arrow presses. Reject full-screen sources and invalid/overflowing destinations. |
| Drag verification | Accessibility cannot read the window frame after mouse-down; the move treated that failure as a successful grab and switched Spaces anyway. | Require valid initial geometry and positive evidence of movement. Missing geometry fails closed. |
| Held modifiers / interrupted moves | Hotkey modifiers remain held past the two-second wait, or the task is cancelled while dragging. | Abort on held modifiers/cancellation, recheck the source desktop after waiting, and release a held synthetic mouse in cleanup. |
| Delayed Dock actions | A new-window request waits while the user changes desktops, clicks elsewhere, stops the tap, or quits the app. | Invalidate stale work; stop delayed activation and fallback clicks when the request/context no longer matches. |
| Preview overflow | An app has more windows than fit across the screen; cards were clipped without scrolling. | Bound the panel width and make the cards horizontally scrollable. Handle an unavailable screen without indexing an empty array. |
| Preview lifecycle | A Space changes or a newer capture starts while an old capture is pending. | Hide on Space changes, cancel old captures, and accept results only for the current generation. |
| Close preview | Closing a window fails or opens an unsaved-document sheet; its card disappeared anyway. | Re-query windows after the close request instead of unconditionally removing the card. |
| Thumbnail memory | Repeated previews accumulated images in an unbounded dictionary. | Use a count-limited, evictable cache; isolate updates to the main actor and reject cached reads after permission loss. |
| Feedback acknowledgement | HTTP 200 contains HTML, an empty body, or malformed JSON; the form claimed success and deleted the draft. | Require an explicit successful JSON acknowledgement, otherwise preserve the draft and show an error. |
| Feedback draft loss | The user edits the message/attachment while an earlier submission is in flight. | Clear only unchanged submitted fields; guard empty and duplicate sends. |
| Process launch failure | Starting `defaults` or `screencapture` throws, then code still waits on an unlaunched process. | Wait only after a successful launch; restore the feedback form on screenshot launch failure. |
| Multiple monitors | The focused window is on a secondary display with different desktop numbering. | Build the menu from that window's display, falling back to the first display only when it cannot be resolved. |
| Debug numeric inputs | Extreme Space counts, negative/nonfinite delays, or malformed glide durations cause conversion traps or unbounded work. | Bound Space switches, serialize them with moves, validate sleep/glide durations, and reject nonfinite glide coordinates. |
| Accessibility revocation | Services continued polling after access was revoked. | Stop preview polling and the event tap while permission is unavailable. |

## Verification

- `./scripts/build.sh`: succeeds and produces `build/SpaceKeeper.app` with both arm64 and x86_64 architectures.
  The generated ad-hoc signature passes `codesign --verify --deep --strict`. The app was not installed or launched.
- `./scripts/test.sh`: seven regression groups pass using only Command Line Tools. Covers Space destination boundaries,
  overflow, missing drag geometry, invalid debug movement arguments, feedback acknowledgement/error handling, preview
  widths, duplicate/empty sends, edits during an in-flight send, and failed-draft preservation.
- The regression runner compiles production sources with a separate entrypoint; it does not send network requests,
  post desktop input, or require Accessibility/Screen Recording access.
- CI now runs this script before packaging. Remote CI has not run because these changes have not been pushed.
- `bash -n scripts/test.sh scripts/build.sh scripts/package.sh` and `git diff --check`: pass.
- XCTest was unavailable in this Mac's Command Line Tools. The standalone runner avoids requiring full Xcode.

## Remaining verification / limitations

- Exercise actual Dock clicking/dragging, unsaved-document close sheets, modifier hold/cancellation, fullscreen crossings,
  and multiple displays using throwaway windows before release. Those interactions were not automated against the user's desktop.
- Test the preview's scrolling and placement visually at different display scales and Dock orientations. The width calculation
  is tested; native visual and pointer interaction are not yet verified.
- Feedback tests use injected senders and fabricated responses. No feedback email was sent. Live service activation,
  acknowledgement format, attachment forwarding, and inbox delivery remain unverified. The current endpoint is unchanged;
  if it returns HTML, the app now reports unconfirmed receipt and retains the draft. FormSubmit documents JSON-oriented
  requests separately: https://formsubmit.co/ajax-documentation . Changing the attachment transport requires its own validation.
- Dock hit-testing still makes synchronous Accessibility calls inside the event tap; a slow/unresponsive Dock can time out
  the tap. This architecture needs native performance investigation before replacing it with cached hit-testing.
- Space movement still relies on private read APIs and timed Mission Control shortcuts. Passing source checks/builds cannot
  establish compatibility across older macOS versions or prove that an interrupted transition lands on the requested Space.
- Existing `String(contentsOf:)` deprecation warning in the optional debug channel remains unrelated to these fixes.
